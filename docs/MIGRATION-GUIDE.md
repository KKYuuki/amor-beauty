# Database Migration Guide

## Overview

This project uses **Drizzle ORM** for database management with PostgreSQL. Migrations are stored in the `drizzle/` directory and are automatically generated by Drizzle Kit.

## Migration Structure

### Directory Layout

```
drizzle/
├── 0000_polite_whirlwind.sql       # Initial schema
├── 0001_sudden_toad_men.sql        # Migration 1
├── 0002_silky_maelstrom.sql        # Migration 2
├── 0003_add_show_in_sales.sql      # Descriptive name example
├── ...
├── 0013_lonely_black_cat.sql       # Latest migration
└── meta/
    ├── _journal.json               # Migration history
    └── *.json                      # Schema snapshots
```

### Naming Convention

Migrations follow the pattern: `{sequence}_{descriptive_name}.sql`

**Examples:**
- `0000_polite_whirlwind.sql` - Initial schema (auto-generated name)
- `0003_add_show_in_sales.sql` - Descriptive manual rename
- `0010_add_services_tables.sql` - Feature-based naming

**Best Practice:** After generating, rename migrations to be descriptive:
```bash
# Auto-generated
0005_lying_stark_industries.sql

# Better (after rename)
0005_add_payroll_tables.sql
```

## Migration Workflow

### 1. Make Schema Changes

Edit files in `server/db/schema/*.ts`:

```typescript
// server/db/schema/inventory.ts
export const inventory = pgTable('inventory', {
    // ... existing columns
    newColumn: text('new_column'),  // Add new column
})
```

### 2. Generate Migration

```bash
bun run db:generate
```

This creates a new SQL file in `drizzle/` and updates `_journal.json`.

### 3. Review Generated SQL

Always review the generated migration before applying:

```bash
# View the latest migration
cat drizzle/0013_lonely_black_cat.sql
```

**Check for:**
- Correct column types
- Proper indexes
- Foreign key constraints
- No accidental data loss

### 4. Apply to Database

```bash
# Push schema changes directly (development)
bun run db:push

# Or run migrations (production)
bun run db:migrate
```

**Note:** `db:push` is for development and alters tables directly. `db:migrate` runs migrations sequentially from `_journal.json`.

### 5. Verify Changes

```bash
# Check tables in database
bun run db:studio
```

## Migration Audit Checklist

When reviewing migrations, verify:

- [ ] **Sequential numbering** - No gaps in sequence (0000, 0001, 0002...)
- [ ] **Journal consistency** - `_journal.json` matches SQL files
- [ ] **Descriptive names** - Migrations renamed from auto-generated to descriptive
- [ ] **Schema match** - Migrations reflect actual schema changes
- [ ] **No orphans** - All migrations have corresponding schema tables

## Troubleshooting

### Migration out of sync

If `_journal.json` doesn't match SQL files:

```bash
# Regenerate journal from SQL files
bun run db:generate
```

### Reset migrations (careful!)

```bash
# Drop all migrations
bun run db:drop

# Regenerate from current schema
bun run db:generate
```

### Schema drift

If database schema differs from code:

```bash
# Pull current schema from database
bun run db:pull
```

## Related Commands

| Command | Description |
|---------|-------------|
| `bun run db:generate` | Generate migration from schema changes |
| `bun run db:push` | Push schema to database (dev) |
| `bun run db:migrate` | Run pending migrations |
| `bun run db:pull` | Pull schema from database |
| `bun run db:drop` | Drop all migrations |
| `bun run db:studio` | Open Drizzle Studio GUI |
| `bun run setup` | Full database setup |
| `bun run seed` | Seed default data |
